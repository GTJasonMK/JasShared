## 原生应用与 MCP

在隔离的应用数据目录运行真实 Linux 桌面窗口和 WebDriver：

- GT 的 MCP 写入在窗口显示并持久化；相同请求 ID 在窗口重载后不重复创建节点。
- 转发中的窗口重载返回 OUTCOME_UNKNOWN，恢复后没有自动重放写操作。
- 无令牌请求返回 401，错误结构在执行前被拒绝。标准 MCP SDK 验证 34 个工具的可发现性、实际输入 schema、稳定 requestId 去重和离线 APP_UNAVAILABLE。
- 编辑器保存旧快照时保留后续草稿，BOM、CRLF、YAML 注释和未知字段得到保留。
- 磁盘文件及草稿变化分别使删除审批失效；未变化的待审批请求在窗口重载后恢复并执行一次删除。

所有测试文件和日志均使用临时目录，原有博客创作文件没有修改。旧审计文件不参与新检查点写入。

## 渲染与交互

Chromium 覆盖 1440、1024、390 和 375px。共享正文、图谱、博客页面、目录与详情交互接受独立渲染复核，未发现新增横向溢出或 pageerror。检查了节点详情开关、小地图、嵌入标签、深浅主题和帮助中的 Mermaid。

补充点击测试修复了 React 严格模式重复渲染时标题 ID 与目录不一致的问题。标题 ID 在 Markdown 解析阶段分配；重复处理和渲染保持相同结果。真实浏览器验证了目录滚动、图片放大和 Escape 关闭。

编辑器主界面 375px 的 11px 横向溢出在基线中已存在；桌面窗口本身设置 900px 最小宽度。本次没有改造这套窄屏工作流。共享预览在同宽度下没有横向溢出。

## 图谱计算

合成链状图谱，预热后运行五次取中位数。单位为毫秒，不代表浏览器绘制帧率。

| 操作 | 1,000 节点 / 999 边 | 10,000 节点 / 9,999 边 |
| --- | ---: | ---: |
| 解析与完整性检查 | 4.33 | 20.04 |
| 校验后序列化 | 3.87 | 31.92 |
| 工作区 revision | 7.02 | 70.74 |
| 命令输入摘要 | 4.34 | 37.42 |
| 最短路径 | 0.35 | 4.69 |

完整性检查、序列化、摘要与最短路径按节点和边线性处理，revision 还需排序。GT 的 2 MiB HTTP 请求上限保持不变；10,000 节点样本的完整导入应走本地文件入口，或通过较小的 MCP 请求增量编辑。

## LLM 输入

相同合成输入覆盖六种文档、五种动作、两种应用模式、选区和分块润色，共比较 126 组真实 messages：105 组逐字相同，21 组仅在图谱规则中改正“跳过坏块寻找有效图谱”的旧说法，要求先修复第一块。用户消息保持相同。

没有调用付费模型，因此未测量生成质量、实际 token、缓存命中或模型消融效果。Windows 和 macOS 原生窗口未实机验证。
