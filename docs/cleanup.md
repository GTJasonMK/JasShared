# 0.2.0 冗余清理与缺陷修复

日期：2026-11-12。五个公共包统一发布 0.2.0，三个应用同步更新固定 Release URL 与完整性锁文件。

## 删除与统一

- 删除内存 tracker 的旧包装、重复恢复入口、图谱颜色别名及未使用类型；执行记录、错误与状态的 TypeScript 类型从 Zod 模型推导。
- 删除只由旧测试使用的正文分段器。图谱代码块使用实际 Markdown 渲染入口，测试验证渲染与非法内容提示。
- 文档保存统一为 `serializeContentDocument`。正文更新保留原始 frontmatter，元数据更新保留注释和未知字段，普通文档无需 frontmatter；仅修改日期也会保存。
- 目录与正文使用相同 Markdown 语法和标题 ID 分配规则。H1 参与去重，H2 至 H4 进入目录，处理内联格式、Setext、长围栏、脚注和已有编号冲突。父组件复用目录提取结果。
- 应用侧删除旧镜像接口、无调用 setter、废弃桥接命令、重复预览组件和未使用设置项；实际调用方、测试与导出一并更新。

删除了 `createInMemoryExecutionTracker`、`extractGraphFromContent`、两种分支序列化 API、`graph-content` 子路径和颜色别名。目录组件现在接收 `headings`。这是开发阶段的明确接口调整，不保留兼容包装。

## 已修复的行为

1. 文件重命名完成后更新当时的活动草稿，保留 I/O 期间的新编辑；较早的文件读取不能覆盖后选文件，关闭文件会使未完成读取失效。
2. 设置和模板读写串行处理，只有 Native 写入成功后才更新状态。读取失败不能用空默认值覆盖原文件，写入失败向调用方报错，弹窗保留输入。
3. 模板保存使用当前元数据和正文，包含尚未保存的元数据修改。
4. Agent 默认使用随机 UUID，指纹按固定顺序排序字段。恢复时检查记录结构与引用，中断会话的任务失败且审批失效；已暂停审批仍可恢复。终态任务不能重新运行，结构化错误保留原代码与详情。
5. LLM 共用一条 HTTP 请求流程，按平台明确选择 fetch，删除无效严格模式、无调用收集模式和旧模型默认值。模型缺失直接报错，Anthropic 请求使用相应认证头且保留全部 system 消息。
6. SSE 完整文本与流共用分帧，处理 UTF-8、跨包 CRLF、多行 data 与末尾帧。坏 JSON、服务端 error、未知响应格式和缺少完成状态不会变成成功；有效正文先交付，再报告同一包中的后续错误。
7. 分块润色失败会停止启动新块并等待在途任务收尾，保留已生成建议。日志追加和轮转串行执行，日志失败单独反馈，不使已生成成果变成重试请求。
8. Native 创建文件原子拒绝已有目标，重命名不会覆盖目标；设置、模板使用原子替换，正常保存保留文件权限。路径检查传播权限错误，目录读取不沿符号链接递归，超过深度限制明确报错。
9. GT 代码导入明确接受 JSON 文件清单，拒绝坏输入与重复路径；中文与特殊字符不会生成重复 ID，相对导入按源文件目录解析。图谱公布的 JSON Schema 包含与运行时相同的非空白约束。
10. 编辑器弹窗复用原生 dialog，显示持久失败反馈并保留输入；关闭后恢复焦点，菜单弹窗使用持久入口作为焦点目标。图片预览关闭后恢复原图片按钮焦点。

## 验证与成本

正式 Release 安装后验证结果如下。应用分别复制到工作区外的独立临时目录，不提供相邻应用源码，再执行 `npm ci`、测试与构建。

| 仓库 | JS/TS 回归 | 其他验证 |
| --- | ---: | --- |
| GT | 34 项通过 | 构建、隔离安装构建、6 项 Rust 测试 |
| JasBlog | 14 项通过 | 构建、lint、隔离安装构建 |
| JasBlogEditor | 167 项通过 | 构建、隔离安装构建、3 项 Rust 测试 |
| JasShared | 32 项通过 | 五包构建、依赖边界、GitHub CI |

合计 247 项 JS/TS、9 项 Rust 回归通过。后端测试使用 60 秒超时。三个应用的锁文件包含正式下载 URL 和 SHA-512 integrity，没有本地路径依赖，其他已锁定依赖版本未改变。共享源码提交 `710dc82` 的 [GitHub CI](https://github.com/GTJasonMK/JasShared/actions/runs/43112184455) 通过。

真实 Linux Tauri 窗口通过草稿保留、版本检查、审批恢复、请求去重和中断不重放检查；标准 MCP SDK 验证 34 个工具、实际输入合同、去重和离线错误。浏览器与独立复核覆盖 375、390、1024、1440px，验证失败后输入、目录跳转、图片放大、Escape 和焦点恢复。修复了原有错误提示的窄屏溢出，普通错误与长路径都完整换行。工作区根路径另有驱动器与 UNC 边界回归。临时文件位于隔离目录，原有博客内容未改写。

合成样本预热后运行七次取中位数：5,000 字符的标题提取约 4.8ms；含 100 个标题、大量内联格式的 185KB 压力样本约 170ms。该压力样本保留原 frontmatter 的保存约 0.29ms，元数据修改保存约 0.66ms。解析与保存按输入长度处理；目录提取仅在内容或展示模式变化时重算，大文档仍有完整 Markdown 解析成本。

本轮没有修改 LLM 提示词或调用付费 API；传输使用模拟响应验证。Windows 和 macOS 未实机验证。文件重命名依赖目标文件系统的 hard link 能力，不支持时明确报错并保留源文件。

首轮去耦合的验证历史见 [validation.md](validation.md)。
