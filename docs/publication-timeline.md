# 首次发布时间

`content-core` 0.7.0 在所有博客文档和摄影作品中统一提供 `publishedAt`。它记录首次发布，后续修改、重新构建、发布重试和撤回后再次公开均保留已有值，不生成更新记录。`date` 与摄影 `takenAt` 继续保留各自原有内容日期和拍摄日期的含义。

`publishedAt` 接受有效的 `YYYY-MM-DD`，或包含秒和时区的 ISO 时间。完整时间归一为 UTC，展示时使用北京时间；历史日期只展示到日，不补造时分。字段由文档或作品自身持有，文件改名和作品排序不会丢失记录。

`site-tools` 的发布流程在校验通过后、构建快照之前写入缺失的首次时间，随后把这些元数据变更一起校验和提交。普通构建只读内容。首次尝试未成功时已记录的时间仍保留，恢复发布沿用它，线上成功状态仍以部署校验为准。

历史数据通过显式 `migrate` 迁移：先备份原始字节，仅把公开 Markdown 已有的 `date` 复制到缺失的 `publishedAt`，保留正文、注释、BOM 和换行。缺少日期的历史项保持待补录，摄影拍摄日期不充当发布时间。重复迁移不重写已完成的内容。

`timeline` 是汇总栏目，不是新内容类型。博客从现有公开内容加载器生成一项一条的记录，草稿和未公开栏目不参与。它支持独立开关、导航名称和静态分页。编辑器通过公共发布属性和摄影属性补录日期、时间；发布后重新读取干净文档与摄影版本，未保存编辑保留，继续受旧磁盘版本的冲突保护。

共享视图复用 `PublicationTime`，列表与详情使用同一个格式化规则。`./back-to-top` 提供独立返回顶部入口，站点级时间线无需引入整个内容视图入口。

验证包括日期与时区、序列化保真、新模板清除旧发布时间、历史迁移备份和重复执行、首发写入在构建前完成、构建失败恢复及后续发布不改时间。安装包单独安装验证核心、视图和工具的正式接口。
